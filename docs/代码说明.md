# 代码说明

## 目录结构

```
src/
├── config.py                      # 统一路径与全局参数
├── 01_data_preprocessing.py       # 数据预处理与聚合
├── 02_model_training.py           # 基线模型（线性回归 + 随机森林）
├── 02e_stratified_model.py        # 三层分层模型（工作日/周末/节假日）
├── 03_visualization.py            # 分析图表生成
├── 04_dispatch_optimization.py    # 调度优化分析
├── 05_prediction_gui.py           # PyQt5 图形化预测系统
└── run_all.py                     # 一键运行入口
```

## 执行流程

```
01_data_preprocessing.py             （可选：需原始 1.2 GB 流水）
       │  原始 CSV → 按「日期×小时×线路」聚合 → 关联天气/节假日
       │  输出 data/aggregated_data.csv
       ▼
data/aggregated_data_full.csv.gz     （随仓库提供，可直接使用）
       │
       ├──→ 02_model_training.py      → models/rf_model.pkl, lr_model.pkl
       │
       └──→ 02e_stratified_model.py   → models/rf_model_workday / weekend / holiday.pkl
                    │
                    ├──→ 03_visualization.py          → figures/*.png
                    ├──→ 04_dispatch_optimization.py  → figures/dispatch/*.png
                    └──→ 05_prediction_gui.py          （图形界面，独立运行）
```

## 配置层

所有脚本通过 `config.py` 定位资源，不依赖当前工作目录：

| 常量 | 指向 | 说明 |
| :--- | :--- | :--- |
| `DATA_DIR` / `RAW_DIR` | `data/` / `data/raw/` | 聚合数据与原始流水 |
| `MODEL_DIR` | `models/` | 训练产物，已被 `.gitignore` 排除 |
| `FIGURE_DIR` / `DISPATCH_FIGURE_DIR` | `figures/` / `figures/dispatch/` | 图表输出 |
| `AGGREGATED_CSV` | `data/aggregated_data_full.csv.gz` | 主数据集，pandas 直接读 gzip |
| `FEATURES` | 7 个特征名 | 保证训练与预测特征顺序一致 |
| `PASSENGERS_PER_BUS` | 35 | 运力换算基准（人/车） |

`ensure_dirs()` 在写文件前创建输出目录；`require_file()` 在输入缺失时给出可操作提示，而不是抛堆栈。

## 各脚本详细说明

### config.py — 全局配置

集中管理路径、特征列表、运力基准与随机种子。新增分析脚本时只需 `from config import ...`。

### 01_data_preprocessing.py — 数据预处理与聚合

**功能**：读取原始刷卡流水与天气、节假日数据，完成清洗、聚合、关联与特征派生。

**处理流程**：
1. 读取 `data/raw/bus_card_records.csv`（或中文原名 `公交刷卡_2023-2024数据_去重后.csv`）
2. 解析刷卡时间，提取小时与日期
3. 按「日期-小时-线路」聚合：
   - `ride_count`：刷卡乘次（`size`）
   - `bus_count`：该时段运营车辆数（`BUSCODE` 唯一计数）
4. 关联天气数据（开尔文转摄氏度、降水量）
5. 关联节假日数据（`is_holiday`），派生 `weekday`、`month`

**输出**：`data/aggregated_data.csv`

**注意**：原始流水约 1.2 GB，未随仓库分发。缺少该文件时脚本会给出明确提示并退出，不影响其余脚本运行。

---

### 02_model_training.py — 基线模型训练

**功能**：用 7 个特征训练线性回归与随机森林，对比评估并做过拟合检测。

**特征**：`hour`, `LINECODE`, `temp_celsius`, `tp`, `is_holiday`, `weekday`, `month`

**训练策略**：8:1:1 划分（训练/验证/测试），`max_depth=10`、`min_samples_leaf=5`、`n_estimators=100`。

**实测结果**：
- 线性回归 R²=0.1548，MAE=32.65（证明客流与特征高度非线性）
- 随机森林 R²=0.8332，MAE=12.48
- 训练集与验证集 R² 差 -0.0006，无过拟合

**输出**：`models/` 下的 `rf_model.pkl`、`lr_model.pkl`、`feature_info.pkl`

---

### 02e_stratified_model.py — 三层分层模型训练

**功能**：按日期类型拆分训练集，分别训练独立随机森林，解决少数类塌陷。

**分层规则**：

| 子模型 | 筛选条件 | 样本量 | R² |
| :--- | :--- | ---: | ---: |
| 工作日 | `is_holiday=0` 且 `weekday<5` | ~281,117 | 0.8412 |
| 周末 | `is_holiday=0` 且 `weekday≥5` | ~108,667 | 0.8346 |
| 节假日 | `is_holiday=1` | ~29,261 | 0.7986 |

**整体性能**：R²=0.8438，MAE=12.12，较统一模型提升 +0.0107。

**输出**：`models/` 下的 `rf_model_workday.pkl`、`rf_model_weekend.pkl`、`rf_model_holiday.pkl`

---

### 03_visualization.py — 分析图表生成

**功能**：加载三层分层模型，生成 10 张分析图表到 `figures/`。

**输出图表**：

| 文件 | 内容 |
| :--- | :--- |
| `feature_importance.png` | 三模型特征重要性对比 |
| `actual_vs_predicted.png` | 预测值 vs 实际值散点 |
| `hourly_prediction.png` | 各时段平均客流预测对比 |
| `error_distribution.png` | 预测误差分布直方图 |
| `route_r2.png` | Top10 线路 R² |
| `route6_bus_forecast.png` | 线路 6 各时段预测乘车量与建议车辆数 |
| `fixed_interval_problem.png` | 固定间隔运力与实际需求对比 |
| `dynamic_interval.png` | 动态间隔运力与实际需求对比 |
| `utilization_comparison.png` | 固定 vs 动态运力利用率对比 |
| `weather_dispatch_advice.png` | 不同天气发车调整建议 |

> 线路 6 单日客流直接取自聚合表的 `ride_count`，无需加载 1.2 GB 原始流水。

---

### 04_dispatch_optimization.py — 调度优化分析

**功能**：计算各时段当前发车间隔、量化天气影响，生成调度优化图表到 `figures/dispatch/`。

**核心计算**：
- **发车间隔**：按「线路 × 小时」对 `bus_count` 取日均，再对各线路取均值，换算为 `60 / 平均车辆数`
- **天气影响**：以舒适天气为基准，计算各天气类型客流变化比例，直接转为发车调整系数
- **运力测算**：`ceil(预测客流 / 35)`

**实测天气影响**：炎热 +35.2%、雨天 -0.3%、寒冷 -10.2%、雪天 -19.2%

**输出**：8 张图表（`hourly_volume.png`、`weather_volume.png`、`workday_vs_holiday.png`、`model_r2_comparison.png` 等）

---

### 05_prediction_gui.py — 图形化预测调度系统

**功能**：基于 PyQt5 的桌面应用，提供可视化客流预测与调度决策界面。

**主要模块**：
- **客流预测**：选线路/日期/天气，实时输出各时段客流量与建议车辆数
- **天气对比**：同屏对比不同天气下的预测差异
- **模型对比**：三层分层 vs 线性回归
- **历史数据**：所选线路的历史客流统计

**技术要点**：按 `is_holiday`/`weekday` 自动路由到对应子模型；天气选项实时联动；动态窗口布局。

### run_all.py — 一键运行

```bash
python src/run_all.py              # 02 → 02e → 03 → 04
python src/run_all.py --with-etl   # 额外先跑 01（需原始流水）
```

逐步调用子进程，任一步失败即中止并提示退出码。

## 相比竞赛版本的工程化改动

原始代码是竞赛期间的一次性分析脚本，为便于他人复现做了以下整理（**算法逻辑未改动**）：

1. **消除硬编码相对路径**：原先依赖 `../../公交刷卡_*.csv` 这类与竞赛目录结构绑定的路径，现统一由 `config.py` 基于 `__file__` 定位，可在任意目录运行。
2. **解除对 1.2 GB 原始数据的依赖**：`03` / `04` 原先为取单线路单日客流和车辆数，会重新加载全量原始流水；现改为使用聚合表已有的 `ride_count` / `bus_count` 字段，运行时间从数分钟降至数秒。
3. **补全 ETL 的 `bus_count` 产出**：原 `01` 只聚合 `ride_count`，而 `04` 需要车辆数，导致重跑 ETL 后流程断裂；现一并统计 `BUSCODE` 唯一计数。
4. **输出目录规范化**：模型统一写入 `models/`，图表写入 `figures/` 与 `figures/dispatch/`，文件名改为英文以避免跨平台中文路径问题。
5. **输入检查与提示**：数据缺失时给出「该放哪个文件、或可以跳过此步」的说明，而不是抛出堆栈。
6. **新增 `run_all.py`**：一条命令跑通全流程。
